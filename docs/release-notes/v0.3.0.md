The racks of 102 ships now come from the game files, so their size, place and stacking are the game's. The hull holograms and outlines come from the same game models, so ships finally line up with their racks. Where the game tilts a rack, the overlay does too: Hull B, Railen, 890 Jump, Prowler Utility, Syulen, M80, Mustang Alpha, Mustang Alpha Vindicator and Cyclone.

Unzip, then start `SC-CargoPlan\CargoPlan.App.exe`; Windows warns that the app is unsigned (**More info → Run anyway**). Check the download against the `.sha256` file ([how](https://github.com/MRiediger/sc-cargoplan/wiki/Installation-and-first-start#check-the-download-optional)). Run the game in **Borderless** window mode. How it works: the [wiki](https://github.com/MRiediger/sc-cargoplan/wiki).

## Ship data

- **Source:** cargo grid data and ship models from [cryon.rocks (Motherlode)](https://cryon.rocks/ops/cargo), extracted from the game files of Star Citizen `4.10.2-LIVE.12913470`. More in the wiki: [Ship data](https://github.com/MRiediger/sc-cargoplan/wiki/Ships-and-cargo-grids#ship-data).
- **8 new ships:** Carrack Expedition, Carrack Expedition w/C8X, Carrack w/C8X, Cyclone, MOLE Carbon Edition, MOLE Talus Edition, Mustang Alpha Vindicator, Valkyrie Liberator Edition. 105 in all.
- **Hull A, B and C** show their spindle extended, the cargo pose of the game model; the Hull A's plates now stand 5 cells apart, as at the cargo elevator.
- **Corsair:** the game takes crates up to 24 SCU, not 32.
- **Three ships still use Fleetyards data** for grids, hologram and outline: 135c, 600i Executive Edition, F7C Hornet Mk II. The game data we use has no model for them yet.

## Changes

- **Max size works again:** the drop-down in the mission editor keeps your pick, with the mouse or the arrow keys, and matches the light or dark theme. The column is now called **Max size**; its tool tip has the whole term (#22, thanks Reikal).
- **Crate lists are grouped:** `6×32+16+4+2+1` instead of every crate, in the editor, the legend and the notices. Type either form into the **Crates** column: `2x32+16` or `32+32+16`; if they don't add up, the row says so (#21).
- **Contracts that say "8 SCU or smaller"** now give max 8. Before, the size was missing, so the overlay assumed the largest crate (`32 SCU?`) and planned with 32s (#22).
- **Mission editor:** long column headers and crate lists wrap instead of being cut off. In the dark theme the selected row and the picked list entry get a calm fill with a teal bar.
- **Ship list:** every ship shows its capacity, `(64 SCU)`; a module configuration shows its own. The mouse wheel scrolls smoothly instead of jumping whole manufacturers, so no ship is skipped and the last one is fully in view.
- **Thousands comma** in the header and the ship list: `56/4,608 · 4,552 free`.
- **Ship files** (for those who write their own): a rack can lie at an angle with the new optional `rotation` (`[yaw, pitch, roll]` in degrees, schema 6). Hologram and outline have their own place (`holoOrigin`, `outlineOrigin`), so correcting one rack's `origin` moves only that rack. `fleetyardsSlug` is now `modelKey`. See [ship-format.md](https://github.com/MRiediger/sc-cargoplan/blob/main/docs/ship-format.md).

## Before you update

- **Your plan loads as it was**, on the racks' new places. Re-plan once if the crates look out of place. **Re-plan for sure** on these 16 ships, whose racks now stack the way the game does: Aurora Mk I (CL, ES, LN, LX, MR, SE), Fortune, Golem OX, Hull C, M80, MOTH, MPUV Tractor, Prowler Utility, Railen, Syulen, Tyilui. A Corsair plan with 32 SCU crates is re-planned when it loads, and the overlay says so.
- **Holograms download once more:** each ship's hologram comes again when first shown, about 0.3 MB per ship, since hull and racks now come from the same game model. The old holograms of v0.2.0 (`holo\holo-v1`, about 65 MB) are deleted; the overlay says so once.
- **Your own ship files** with `fleetyardsSlug` keep working; a file with both names is an error.
- **Going back to 0.2.0** works: it reads the plan and the settings 0.3.0 saved, and downloads its own holograms again. Ship files of your own that use `rotation` or `modelKey` need 0.3.0.

## Known issues

- **With blocks and gaps:** a contract that comes in by sync moves nothing, so it can wait because the gaps split up the free room. **Re-plan** lays it in. A crate turned to keep a gap stays turned if that gap goes anyway.
- **Unsigned, no auto-update:** Windows warns at the first start of every version; check the releases for new ones.
- **Racks are placed to the nearest whole crate cell:** a rack can sit up to about half a meter off its place in the game. Its size and the crates in it are not affected.
- **Door limits:** the game files describe the hold, not its door, so some racks may have a door limit the app doesn't know.
- **135c, 600i Executive Edition, F7C Hornet Mk II:** their racks lie in a generated row, not where they are in the ship.
- **The Retaliator is not included.**
- **A crate under an empty rack** in front of it can't be clicked in the ship view. Turn the view, or use its line in the legend.
- **Very large ships zoomed in all the way** (such as the Hull C): the camera can stand among the racks, and parts close to it are cut off. Zoom out a little.
- **Hologram behind a half-transparent crate:** the parts of the hologram behind it don't show; hardly visible at the default fill.
- **Ship holograms** are made from CIG's ship models and are not under MIT. They live in a release of their own, [`holo-v2`](https://github.com/MRiediger/sc-cargoplan/releases/tag/holo-v2), with its own NOTICE, not in this ZIP. The app downloads them only from there, one file per ship when you pick a hologram look; **Download ship holograms** in the settings switches it off.

More, with workarounds: [Troubleshooting › Known issues](https://github.com/MRiediger/sc-cargoplan/wiki/Troubleshooting#known-issues).
