Ship data from Star Citizen 4.10.3 with three new ships, holograms from the new game models, and a header that keeps the
ship name on a narrow overlay.

## Updating

- **From v0.5.0:** the overlay's bottom line says `Update available · v0.5.1`. Click **Update**; CargoPlan restarts
  with your plan, your ticks and the view as they were. This is the first self-update – it downloads the full package
  (about 90 MB).
- **From v0.4.0 or older:** update by hand this once, as described in
  [Upgrading from v0.4.0 or older](https://github.com/MRiediger/sc-cargoplan/releases/tag/v0.5.0) of v0.5.0, with
  `SC-CargoPlan-v0.5.1-win-x64.zip` below.

Check the download against the `.sha256` file
([how](https://github.com/MRiediger/sc-cargoplan/wiki/Installation-and-first-start#check-the-download-optional)). Run
the game in **Borderless** window mode.

## Ship data

- **Source:** cargo grid data and ship models from [cryon.rocks (Motherlode)](https://cryon.rocks/ops/cargo), extracted
  from the game files of Star Citizen `4.10.3-LIVE.13165946`. 108 ships in all.
- **3 new ships,** with racks and hologram: RSI Galaxy (720 SCU), Anvil Liberator (400 SCU), Aegis Retaliator (74 SCU).
- **ORIG 350r:** the game added a second cargo grid in front. It now holds 12 SCU in two racks (8 + 4), not 4.
- **New holograms for 12 ships,** from their new game models: Paladin, Cutter, Cutter Rambler, Cutter Scout, Prowler
  Utility, Railen, Tyilui, Starlancer Max, Starlancer TAC, Constellation Phoenix, Constellation Taurus, Perseus. Their
  racks stay where they were.
- **Cyclone:** no longer in the game data we use. It keeps its racks and hologram as before.

## Changes

- **The header keeps the ship name.** On a narrow overlay `All stops delivered.` goes first (its words stay in the tool
  tip over the numbers), then the numbers turn short: `56/64`, or `56/64 +16` while 16 SCU wait for room. Then the tool
  buttons move to a second line; gear, X and the padlock stay where they are. While the overlay is locked, the buttons
  and the second line are gone. The overlay can't be made narrower than the longest ship name needs.
  More: [Overlay basics › On a narrow overlay](https://github.com/MRiediger/sc-cargoplan/wiki/Overlay-basics#on-a-narrow-overlay).
- **Contract reader:** ONNX Runtime 1.32.0 (was 1.31.1).

## Before you update

- **Holograms download once more:** each ship's hologram comes again when first shown, about 0.3 MB per ship. The old
  ones (`holo\holo-v2` in `%LocalAppData%\SC-CargoPlan`) are deleted; the overlay says so once.
- **Saved plans load as they were.** ORIG 350r: a 350r plan saved before shows its crates on the new front rack.
  **Re-plan** once.

## Known issues

Updating itself is still new:

- **This is the first self-update – it downloads the full package** (about 90 MB). Small updates come only after that,
  and only if you are exactly one version behind.
- **Going back to v0.4.0** after v0.5.0 or later saved your settings: v0.4.0 starts with default settings and says so.
  To keep yours, close the overlay first, open `%LocalAppData%\SC-CargoPlan\settings.json` and delete the
  `"updates": { … }` block at its end and the comma at the end of the line before it.
- **A folder below `Program Files`:** the update asks Windows for administrator rights. Say No and the old version comes
  back with `Update failed · cancelled`; **Retry** asks again without downloading again.
- **Velopack, the update tool, keeps its own log** in `%LocalAppData%\velopack\velopack_CargoPlan.log`.
- **Star Citizen as administrator:** run CargoPlan as administrator too. After the Windows prompt from a
  `Program Files` folder it runs without administrator rights, so start it again as administrator.
- **Rows in the editor you haven't planned** are lost when you click **Update**, as when you close CargoPlan.

Ships and holograms:

- **v0.1 and v0.2 lose their holograms:** their hologram release (`holo-v1`) will be removed. They show the flat outline
  instead; update to get holograms again.
- **135c, 600i Executive Edition, F7C Hornet Mk II** still use Fleetyards data: their racks lie in a generated row, not
  where they are in the ship.

More, with workarounds: [Troubleshooting › Known issues](https://github.com/MRiediger/sc-cargoplan/wiki/Troubleshooting#known-issues).
