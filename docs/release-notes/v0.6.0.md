Ship data now come as a monthly release of their own and update themselves, without a new app version. The first new
ship this way is the GAMA Hyun. Holograms follow the ship data.

## Updating

- **From v0.5.1 or v0.5.0:** the overlay's bottom line says `Update available · v0.6.0`. Click **Update**; CargoPlan
  restarts with your plan, your ticks and the view as they were. If v0.5.1 came to you through that line, only the
  changes are downloaded; otherwise the full package (about 90 MB).
- **From v0.4.0 or older:** update by hand this once, as described in
  [Upgrading from v0.4.0 or older](https://github.com/MRiediger/sc-cargoplan/releases/tag/v0.5.0) of v0.5.0, with
  `SC-CargoPlan-v0.6.0-win-x64.zip` below.

Check the download against the `.sha256` file
([how](https://github.com/MRiediger/sc-cargoplan/wiki/Installation-and-first-start#check-the-download-optional)). Run
the game in **Borderless** window mode.

## Ship data

- **A channel of their own:** racks, outlines and holograms are now built and published in
  [sc-cargoplan-shipdata](https://github.com/MRiediger/sc-cargoplan-shipdata/releases). It is rebuilt once a month from
  the Motherlode data; if anything changed, there is a new data release. Once per start CargoPlan asks for it and offers
  it at the bottom of the overlay: `Ship data update available · 2026.12` with **Update** and **Skip this version**.
  **Update** downloads about 100 KB, checks every file and restarts CargoPlan with your plan and ticks.
- **In this ZIP:** ship data `2026.11.1`, cargo grids from [cryon.rocks (Motherlode)](https://cryon.rocks/ops/cargo),
  extracted from the game files of Star Citizen `4.10.3-LIVE.13165946`. 109 ships and one cargo module configuration.
- **New ship:** GAMA Hyun (32 SCU), with its rack and hologram.
- **F7C Hornet Mk II:** rack and hologram now come from the game files, no longer from Fleetyards. Still 2 SCU.
- All other ships as in v0.5.1.

## Changes

- **Holograms come with the ship data.** Each data release carries its holograms; CargoPlan downloads one file per ship
  from the release in use when you pick the ship. If a data release offers none, ships show their outline and the
  settings say so under **Download ship holograms**.
- **Settings › Ship data:** the data in use (`In use: 2026.11.1 (built in)`, or `(downloaded)`), **Check for ship data
  updates on startup**, **Check now**, and a skipped release with **Clear**.
- **A saved plan with a rack the ship no longer has** is planned anew for the ship's racks
  (`Plan was made for other racks, re-planned for …`), ticks kept. Before, the plan was set aside.
- **Command line:** `CargoPlan.Cli.exe ships --version` names the ship data in use and where they are.

## Network access

CargoPlan makes three kinds of requests, all of them downloads (GET) from github.com. Nothing about you or your PC is
sent. Each has its own switch in the settings:

1. **App update check** (section *Updates*, **Check for updates on startup**): once per start, the release list of this
   project. The new version is downloaded only when you click **Update**.
2. **Ship data check** (section *Ship data*, **Check for ship data updates on startup**): once per start, the
   `manifest.json` of the latest data release (about 130 KB). `ships.zip` is downloaded only when you click **Update**.
3. **Ship holograms** (section *Ship view*, **Download ship holograms**): one file per ship (about 0.3 MB) from the
   data release in use, when you pick a ship while a hologram look is on.

Without a network CargoPlan starts and plans as before: the ship data are in the ZIP.

## Before you update

- **Holograms download once more.** The old ones (`holo\holo-v3` in `%LocalAppData%\SC-CargoPlan`) are deleted and the
  overlay says so once: `Ship holograms updated to match the new rack data – each ship re-downloads when first shown`.
- **Saved plans load as they were,** your ticks too.

## Known issues

Ship data:

- **Old ship data lose their holograms:** only the last two data releases keep their holograms on GitHub. If you skip
  ship data updates for months, or switch the check off, ships whose hologram you haven't downloaded yet show their
  outline. **Update** the ship data (bottom line, or **Check now** in the settings) to get them back.
- **Going back to v0.5.x** after v0.6.0 saved your settings: v0.5.x starts with default settings and says so. To keep
  yours, close the overlay first, open `%LocalAppData%\SC-CargoPlan\settings.json` and delete the
  `"shipData": { … }` block and the comma at the end of the line before it. v0.5.x also downloads its holograms again.
- **135c and 600i Executive Edition** still use Fleetyards data: their racks lie in a generated row, not where they are
  in the ship.

Updating:

- **Small updates only one version apart:** the first update after unpacking a ZIP, or across more than one version,
  downloads the full package (about 90 MB).
- **Going back to v0.4.0** after v0.5.0 or later saved your settings: v0.4.0 starts with default settings and says so.
  To keep yours, delete the `"updates": { … }` block as above, and `"shipData": { … }` too.
- **A folder below `Program Files`:** the update asks Windows for administrator rights. Say No and the old version comes
  back with `Update failed · cancelled`; **Retry** asks again without downloading again. Ship data updates don't ask:
  they go to `%LocalAppData%\SC-CargoPlan\ships`.
- **Velopack, the update tool, keeps its own log** in `%LocalAppData%\velopack\velopack_CargoPlan.log`.
- **Star Citizen as administrator:** run CargoPlan as administrator too. After the Windows prompt from a
  `Program Files` folder it runs without administrator rights, so start it again as administrator.
- **Rows in the editor you haven't planned** are lost when you click **Update**, either one, as when you close
  CargoPlan.

More, with workarounds: [Troubleshooting › Known issues](https://github.com/MRiediger/sc-cargoplan/wiki/Troubleshooting#known-issues).
