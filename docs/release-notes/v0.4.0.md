ContractTracker is no longer needed – open a contract in the mobiGlas and press F3.

Unzip, then start `SC-CargoPlan\CargoPlan.App.exe`; Windows warns that the app is unsigned (**More info → Run anyway**). Check the download against the `.sha256` file ([how](https://github.com/MRiediger/sc-cargoplan/wiki/Installation-and-first-start#check-the-download-optional)). Run the game in **Borderless** window mode. How it works: the [wiki](https://github.com/MRiediger/sc-cargoplan/wiki).

## Highlights

- **Press F3 on an open contract: CargoPlan reads it itself and adds it to the plan; or type it in the editor.** It is read on your screen by CargoPlan itself (RapidOcrNet with PaddleOCR's PP-OCRv5 models, Apache-2.0 – see `models/NOTICE.md`). Nothing is sent anywhere, and nothing is injected into the game.
- **Each contract is a mission of its own**, under a header such as `From Everus Harbor · #3`. Nothing that is already on board moves.
- **Offer, then accepted:** scan the offer to see whether it fits. The game rolls the amounts again when you accept, so press F3 once more on the accepted contract: `Updated #3 · quantities changed`. The mission keeps its number and its place; an offer you don't take goes with **Undo**.
- **The editor's Scan button** does the same as F3. CargoPlan's windows over the contract blink away for the moment of the picture: that blink is the sign a scan runs.

How it works: [Scanning contracts](https://github.com/MRiediger/sc-cargoplan/wiki/Scanning-contracts).

## Changes

- **Hotkeys:** F keys now work without Ctrl, Alt or Win (F12 stays reserved). F3 is the first hotkey set by default. The key reaches the game too: if F3 does something in your Star Citizen key bindings, pick another one in the settings, section **Hotkeys**.
- **Turn scanning off** by clearing the scan key. CargoPlan then doesn't load its contract reader at start: about 90 MB less memory right after the start, and none of the growth that comes with scans.
- **Download and memory:** the contract reader and its models make the download about 87 MB instead of 64 MB. After many scans CargoPlan uses up to about 900 MB of memory.
- **For bug reports:** start `CargoPlan.App.exe --keep-scans` and each scan leaves the picture it read in `%LocalAppData%\SC-CargoPlan\scans` (the last 20, about 50 MB together). `CargoPlan.Cli.exe scan <screenshot.png>` shows what CargoPlan reads in a screenshot. How: [Report a wrong scan](https://github.com/MRiediger/sc-cargoplan/wiki/Scanning-contracts#report-a-wrong-scan).
- **The ContractTracker import is gone:** its settings section, the Sync hotkey and the command-line `contracts` command. CargoPlan began as a companion to ContractTracker; thanks for carrying the first four releases.
- **An unreadable `plan.json` is kept:** if the plan can't be loaded, the first change moves the old file aside as `plan.json.unreadable-<date>` instead of overwriting it.

## Before you update

- **`settings.json`** is written in a new format. A hotkey you had set for **Sync from ContractTracker** is removed; an amber line says which one, once. The old file stays as `settings.json.bak`: to go back to v0.3.x, rename it to `settings.json`.
- **`plan.json`:** contracts from ContractTracker in your plan become scan missions `#1`, `#2` … when v0.4.0 loads it; their crates and ticks stay.
- **Going back to v0.3.x: copy `plan.json` first.** v0.3.x can't read the new plan format and overwrites the file on its first change.
- **Mission files** of schema 1 and 2 (written only before v0.1.0) are refused; [change `schemaVersion` to 4](https://github.com/MRiediger/sc-cargoplan/blob/main/docs/mission-format.md#schema-1-and-2-refused).
- **ContractTracker** isn't needed any more. If it still runs, it reacts to F3 too, and CargoPlan says so.

## Known issues

Reading contracts is new in v0.4.0:

- Checked at 3440×1440 and 1920×1080 only. If a scan finds no contract on 32:9, 16:10 or 4K, start `CargoPlan.App.exe --keep-scans`, scan again and attach the picture from `%LocalAppData%\SC-CargoPlan\scans` to a [bug report](https://github.com/MRiediger/sc-cargoplan/issues/new?template=bug.yml).
- A contract whose destinations run past one mobiGlas page is read as far as it shows; the legend says `⚠ 1 of 3 destinations` when the contract tells.
- ContractTracker also reacts to F3: while it runs, CargoPlan says so. Pick another key or close ContractTracker.
- Two contracts with the same route and reward count as one: add the second in the editor.
- CargoPlan's windows over the contract blink briefly during a scan.
- After many scans CargoPlan uses up to about 900 MB of memory. Clear the scan key in the settings and the reader doesn't load at all.

More, with workarounds: [Troubleshooting › Known issues](https://github.com/MRiediger/sc-cargoplan/wiki/Troubleshooting#known-issues).
