## Upgrading from v0.4.0 or older (one-time manual step)

v0.4.0 and older can't update themselves, so get v0.5.0 by hand this once:

1. Download `SC-CargoPlan-v0.5.0-win-x64.zip` below.
2. Right-click it → **Extract All** into a **new** folder; Windows suggests one named like the ZIP. Don't extract it over
   your old `SC-CargoPlan` folder: the ZIP has no folder of its own any more, and the old files would stay next to the
   new ones. Pick a folder you can write to, not `Program Files`.
3. Start **`SC-CargoPlan.exe`** in the new folder. Windows warns that the app is unsigned: **More info → Run anyway**.
4. Your settings and your plan are already there: they live in `%LocalAppData%\SC-CargoPlan`, not in the program folder.
5. Delete the old `SC-CargoPlan` folder. A taskbar icon or shortcut you pinned still points to it: unpin it and pin the
   new one.

From now on CargoPlan updates itself.

Coming from v0.3.x? Read [Before you update](https://github.com/MRiediger/sc-cargoplan/releases/tag/v0.4.0) of v0.4.0
too. Check the download against the `.sha256` file
([how](https://github.com/MRiediger/sc-cargoplan/wiki/Installation-and-first-start#check-the-download-optional)). Run
the game in **Borderless** window mode.

## What's new

- **CargoPlan updates itself.** When a new version is out, the overlay's bottom line says `Update available · v0.5.1`
  with **Update** and **Skip this version**. **Update** downloads it (`Downloading update · 42 %`), closes CargoPlan,
  swaps the files while a small progress window shows, and starts the new version with your plan, your ticks, the view
  and the overlay's place as they were. **Skip this version** hides that one version; a newer one is offered again.
  While the overlay is locked, the line shows only its text: unlock it to click.
- **Settings → Updates:** *Check for updates on startup*, the version you skipped with **Clear**, and **Check now**.
- **What it sends:** once per start, after the overlay is up, CargoPlan asks GitHub's release list of this project
  whether a newer version is out. Nothing about you or your PC is sent, and nothing is downloaded until you click
  **Update**.
- **Turn off** *Check for updates on startup* and CargoPlan makes no request at all; **Check now** asks only when you
  click it.

How it works and what to do when an update fails: [Updates](https://github.com/MRiediger/sc-cargoplan/wiki/Updates).

## Changes

- **New folder layout:** `SC-CargoPlan.exe` starts CargoPlan, `Update.exe` swaps it, the app itself lives in `current\`.
  After the first update a `packages\` folder holds the downloaded version.
- **Start switches** go to `SC-CargoPlan.exe`, e.g. `SC-CargoPlan.exe --keep-scans`. The command-line tool is now
  `current\CargoPlan.Cli.exe`.
- **Download:** about 90 MB.

## Known issues

Updating itself is new in v0.5.0:

- **Going back to v0.4.0** after v0.5.0 saved your settings: v0.4.0 starts with default settings and says so. To keep
  yours, close the overlay first, open `%LocalAppData%\SC-CargoPlan\settings.json` and delete the `"updates": { … }`
  block at its end and the comma at the end of the line before it.
- **A folder below `Program Files`:** the update asks Windows for administrator rights. After the swap CargoPlan runs as
  before, not as administrator. Say No and the old version comes back with `Update failed · cancelled`; **Retry** asks
  again without downloading again.
- **The first update downloads the whole version** (about 90 MB). Small updates come only after that, and only if you
  are exactly one version behind.
- **Pinned shortcuts and taskbar icons** of v0.4.0 point to the old folder, and the taskbar groups CargoPlan anew.
- **Velopack, the update tool, keeps its own log** in `%LocalAppData%\velopack\velopack_CargoPlan.log`.
- **Star Citizen as administrator:** run CargoPlan as administrator too. An update starts it again the way you started
  it; after the Windows prompt from a `Program Files` folder it runs without administrator rights, so start it again as
  administrator.
- **Rows in the editor you haven't planned** are lost when you click **Update**, as when you close CargoPlan.

More, with workarounds: [Troubleshooting › Known issues](https://github.com/MRiediger/sc-cargoplan/wiki/Troubleshooting#known-issues).
